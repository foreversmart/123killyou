# 《红烛无声》逐景实现索引

本表对照 `story/mini_script.md` 的 01—12 话，记录当前规则、分镜状态、人物构图、道具与声音的实际连接。`sceneKey` 是剧情场景，`shotKey` 是同一场景中的演出状态；同一房间的不同状态共享床、门、窗和矮桌的位置，再改变人物、烛光、道具与对白。

## 共同约定

- 新游戏由 `Engine.Initial → StartMiniStory` 建立 `mini_arrival / arrival_gate`，先显示片头与开始界面，期间隐藏底部对白框，再以约 36 秒从半山腰开始的大巴盘山公路行车和约 9 秒山门群像交代抵达；大巴从半山腰的画面边缘驶入，直路保持速度、进入折返弯道时随道路曲率平顺减速，出弯后再逐步恢复；镜头从车身上方略高的位置随车辆持续向寺庙门口缓慢推进，直接在山门前结束，不再先拉到远方再重新拉近。山路行车开始时循环播放 `opening_bus_horror.mp3`，保持克制的背景音量；进入山门抵达阶段后约 2.5 秒渐弱，开场结束时停止并重置。山路与山门均使用实时 3D 摄像机衔接。山门群像显出时先播放林岚“坐了这么久的车，腿都麻了……终于到了。先下车活动一下”，对白框覆盖众人参观画面；约 9 秒抵达阶段结束后，同一画布、机位和人物动作继续承接其余四句对白。恢复存档只重听当前对白。人物的话由该人物说，主角直接看到和听到的信息不进入对白。
- 开场时序进入 `alighting` 时，已经呈现正式山门 `story` 画布，三位同伴和陆沉缓步参观、驻足聊天；`app/game` 的 `PlayerStatus` 顶部状态栏与第一句对白框一同显示在开场画面上方和底部；进入 `arrival_gate` 正片后，状态栏保持可见。片头、开始界面与山路行车仍保持原有满幅开场画面。
- `actors` 保存姓名、角色、位置、动作、头像和可见性；前端依据这些状态画同行 NPC 并标记正在说话者。主角通常由镜头代表；08 的同行转场与抵达后的 listen_door 同时绘制赵熙和已核对同伴，12 的返车转场同时绘制赵熙与三位同行游客，不添加未知占位；首次正常睡下的 `room_sleep_wait`、逃回后睡下的 `escape_sleep_wait` 与未点烛睡下的 `room_ghost_wait` 共用床侧机位和 53 骨骼赵熙模型，完整显示约 3.2 秒走到床侧，先坐到床沿，再自然躺下并保持呼吸，等待结束后回到第一视角；门外声源不隔门显示实体。移动转场使用廊柱、檐下或侧门外的固定远处机位，像隔着建筑观察队伍；镜头不跟随、不推进、不在抵达前翻转，人物自行穿过取景范围。转场与到达后的 NPC 按远近、步距和朝向错落站位；去登记室、回房等路线走到回廊侧门阈值前减速停步并转向，直接切入目的地首镜头；去晚膳的回廊段走到尽头后保持行进朝向、不转身，直接切到大殿继续行走，均不把人物推进尽头封墙；返程时四位游客一起朝大巴旁汇合，再依次沿车门踏步登车，陆沉留在寺门内送行。
- 道具由环境画面和微光热点共同呈现；鼠标或语音都把命令提交给后端，不在前端自行判定生死、吃粥或杯筊结果。
- 开启语音后，`dialogueNext` 只接续安全对白、已主动开始的经文和投掷后的结果。危险选择前会停下；主动作出调查也会打断接续。
- “重听当前对白 / 重听这句 / 再说一遍”只重播当前人物原句，保留原说话者；无人物对白时重听当前环境音，不补读环境描述，不推进分镜、经文、进食或投掷。
- 每句对白遵循“先看见—再动作—才开口”：先把镜头停在物件或声源上，完成一个可见动作，再播放与眼前所见有关的短句。角色说完后保留环境声间隔，等位置、光线或声源发生变化后才进入下一句。
- 直接可见、可听的事实由场景、道具近景、光影与有方位的环境音表达；观察更新 `sceneText / lastAction` 并清空人物对白，不进入人物或旁白 TTS。书页、房牌和凭证的已知文字在物件视图中阅读。
- “赵熙·心声”只保留少量真实感受、记忆与未证实的猜想，不复述刚呈现的事实或预先给出生存答案。赵熙实际念经使用“赵熙”出声。危险判断、动物拟声、杯筊、开门和逃跑期间暂停自动对白，静音、识别失败和重听不推进危险状态。
- 未匹配剧情的有效发言进入在场 NPC 的独立问答，依据当前场景和最近问答回应；不知道就说明，意思不明才澄清。普通跑题本轮不改变镜头、不扣虔诚度、不替玩家做用餐选择。空回答、超时和重复近期台词在播放、保存前拦截并明确反馈，保留原有进度；无台词观察镜头不视为生成失败。
- 安全接话只限 `mini_arrival / mini_register / mini_refectory / mini_corridor_candle / mini_dawn`：原有 `dialogueNext` 是该场景的安全对白或既定转场，本轮由在场 NPC 回答且场景、镜头和面板未改变时，保留待续行。NPC 先简短回答本次发言，播放完成并等待后才继续原来的下一句或转场；连续发言重置等待。登记问“你是谁”、斋堂问“为什么有肉”等固定短答同样适用。没有待续行时不凭空开启，主动调查、歧义、缺席人物与危险段不恢复计时；回廊仍停在领烛前，天亮上车仍由玩家决定。

## 实时 3D 演出连接

- `world/continuity_key.ts` 按实际地点、昼夜、演出模式与存档 `runId` 划分连续演出；同地点的 `sceneKey / shotKey / flags` 更新不再触发整屏闪暗或归零世界时钟。`create_world.ts` 复用未变化的建筑和植被，`renderer/draws.ts` 按节点路径与几何内容保留 GPU 缓冲和绑定，只释放退出画面的资源。`world_view/continuity.ts` 与 `world_character/continuity.ts` 按人物身份和实际动作保留独立进度，新动作从当前姿态约 0.42 秒平滑接续，覆盖位置、朝向、关节和手持道具；`prop_continuity.ts` 使新投筊、开门从自己的起点播放，烛火与既有动作不断相位。`player_controls.ts` 保留同机位下的位置、视线与拖动，物件特写约 0.42 秒平滑移镜；暂停同时冻结动作与移镜。真实换场、昼夜切换、死亡及读档分支重新开始演出，后端的选择、道具、语音和存档结算不变。
- scene/world_view 挂载 WebGPU 画布；scene/renderer 按 Tidewater 的方式执行帧循环、材质着色、深度与阴影渲染，采用线性颜色、GGX、基础色/法线/ARM 贴图、叶片透明阴影与全景天空反射。远景镜头按距离调整近裁面，保留薄层物件的深度精度；山路阴影范围覆盖车辆与附近林木，投影中心对齐阴影纹素，边缘平滑淡出，叶片以 MSAA 覆盖率和阴影 mip 采样减轻移动闪烁。resources.ts 读取本地素材，draws.ts 共享网格缓冲；行驶大巴的可见车身与轮胎不参与细节阴影投射，使用独立的低模车身轮廓投射干净接地阴影，并关闭车身的方向光阴影接收，避免车身面板、轮拱和轮胎重叠造成黑影。
- `temple_palette.ts` 与 `temple_ornament.ts` 统一建筑的朱漆、青绿、靛色和磨损金箔，以及彩绘梁枋与悬塑壁龛；`temple_carving.ts` 构建卷云和莲花，`temple_shrine_crown.ts` 构建三层楼阁龛顶与小型金身；`architecture.ts/plaque` 统一实时牌匾的深栗漆木、双层金边、凸起金字、侧龙卷云和莲花水波，`compound_hall.ts` 将 `temple_layout.ts` 的 14 栋建筑名称挂到门面并在远景简化。`temple_paint` / `temple_relief` 的基础色、法线和 ARM 由本地素材库读取。山门与公路远景共用门楼和殿宇，回廊、登记室、斋堂、门房、偷听偏房及大殿/偏殿依各自空间复用装饰。悬塑人物仅是静止建筑几何与表面，不进入 actors 或声音路由；装饰保持门窗、互动锚点、通道和既有昼夜状态。
- `temple_window.ts` 统一窗体的烟灰旧木多层边框、回纹团花雕扇与折线菱花格。`architecture.ts/windowLattice` 将登记室、斋堂、门房、偷听偏房、偏殿和大殿高窗接入同一构件；`courtyard_rooms.ts` 用三联雕窗呈现东院四间客房，`courtyard_walls.ts` 的院墙和花园窗口保留真实通透格心；`temple_facade.ts/timberBay` 覆盖山门与 `temple_compound.ts` 中各栋配院、服务建筑和殿宇。生活房间窗保留灰蓝透光层，白天与夜间由原 daylight 状态控制；`room_shell.ts` 和 `courtyard_rooms.ts` 绕窗口拆分墙体，移除窗后的实墙与重叠纸框，原床、门、窗坐标、门闩和交互锚点不移动。远景只减少小雕刻，保留深色窗框轮廓。
- scene/world/scene_state.ts 将原 sceneKey / shotKey 映射到山门、登记室、斋堂、回廊、门房、半掩偏房、偏殿、大殿与山路。placement.ts 保存米制空间中的机位、人物和道具锚点，热点由投影矩阵定位；exterior.ts 的东院回廊两端挂载 `corridor_to_maha_vira` 大殿侧门与 `corridor_to_side_hall` 偏殿回廊门楼，`corridor_side_hall.ts` 把偏殿门楼后的地坪、侧墙、后墙和瓦顶补齐；登记室进出和大殿横移都以这段古朴回廊作为中间镜头。

- 模仿已听过的猫叫或鸟叫：记录 `animal_call_passed`，原路退回。
- 直接跑回房并关门：要求真同伴在场且红烛仍亮；缺任一条件会死亡。
- 跑向大殿：进入神公路线。
- 明确跑向后山、钟楼或陌生偏房：死亡。
- 退回后先停留一两秒，再由主角说“刚刚真的是太惊险了，那究竟是什么怪物”，给出“躺下睡觉 / 再去看看外面”。每次选择睡下都进入 `escape_sleep_wait` 并显示“过了好一会儿”，床侧机位复用首次睡下的赵熙走到床侧、坐到床沿再自然躺下和呼吸演出，正常等待总长约 6.6 秒后才进入 11；不会回到最初入睡前重复整夜。

## 死亡、重试与声音核验

- 死亡进入 `mini_death`，`shotKey=death_<来源 sceneKey>`，`retryScene` 记录来源；所有死亡分支保留来源场景环境，只表现鬼影冲入和随后出现的地面血泊，删除额外绘制的人形、角色身体、尸体与肢体。命中伴随低沉撕裂音效、黑红闪光、屏幕震颤，鬼影冲近后定格保留在左侧，地面为面积较小、分散且无高光/厚重投影的平涂血迹，右侧显示死亡结算卡；减少动态模式同样保留鬼影，卡片提供“从最近安全节点重试”和“从山门重新开始”。重试保留本局已学经文、调查、吃粥选择，清除失败和投掷等临时状态。神公失败特殊回退到已观察剥皮的 08；“重新开始”才建立全新山门开局。
- 打更使用清楚的金属锣音色，二更两声、三更三声、假报晓四声；假报晓余响结束后再播放一次远处钟声，钟与锣的音色可辨。真正五更保留五声更锣以及鸡鸣、檐鸟。四下敲门是独立事件，不是四更；全部敲门声保持木门质感、原有次数、间隔和静默。
